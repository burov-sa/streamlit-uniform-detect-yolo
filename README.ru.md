# Сервис оценки внешнего вида сотрудников

Приложение на Streamlit для автоматической оценки соответствия внешнего вида сотрудников униформе с использованием детекции объектов YOLOv8. Сервис обнаруживает предметы униформы и нарушения на изображениях, видеофайлах или в потоке с камеры и формирует подробный отчёт.

## Возможности

- Три режима работы: изображение, видеозапись, камера.
- Проверка комплектности униформы по настраиваемой спецификации.
- Обнаружение нарушений: отсутствие предметов, превышение количества, специфические нарушения (расстёгнутая одежда, загрязнение и т.п.).
- Редактирование комплектов униформы прямо из боковой панели; изменения сохраняются в `config.yml`.
- Управление моделями: выбор из списка YOLO-моделей в `config.yml` или использование модели по умолчанию.
- Подавление дубликатов по IoU, чтобы избежать завышенных счётчиков.
- Обработка в реальном времени в режиме камеры через WebRTC.

## Требования

- Python 3.10+
- `ffmpeg` (опционально, для конвертации видео в H.264)

## Установка

```bash
git clone <repository-url>
cd <repository-name>
pip install -r requirements.txt
```

Поместите пользовательские веса YOLO в папку `models/`. Модель по умолчанию `yolov8n.pt` скачивается автоматически при первом запуске.

## Запуск

```bash
streamlit run main.py
```

### Элементы управления в боковой панели

- **Тип входных данных** — `Изображение`, `Видеозапись`, `Камера`.
- **Проверяемый комплект одежды** — выбор спецификации униформы для проверки.
- **Вкладки** — просмотр (📋), редактирование (📝), удаление (❌) выбранного комплекта. Изменения записываются в `config.yml`.
- **Порог обнаружения** — порог уверенности детектора (0–100 %, отображается как 0.0–1.0).
- **Алгоритм распознавания** — выбор из `model_names` в `config.yml` или модель по умолчанию.

### Режим «Изображение»

1. Загрузите одно или несколько изображений (`.jpg`, `.jpeg`, `.png`, `.bmp`, `.dib`).
2. Нажмите **Оценить внешний вид**.
3. Размеченные изображения отображаются во вкладке `🗃`.
4. Таблица соответствия отображается во вкладке `📈`: каждый компонент униформы с колонками `наличие` и `нарушения`.

### Режим «Видеозапись»

1. Загрузите один или несколько видеофайлов (`.mp4`, `.mov`, `.avi`).
2. Нажмите **Оценить внешний вид**.
3. Обработанные видео доступны для просмотра и скачивания.
4. Таблица соответствия строится по максимальному одновременному количеству обнаруженных объектов по всем кадрам.

### Режим «Камера»

1. Разрешите доступ к камере в браузере.
2. Поток обрабатывается кадр за кадром; дубликаты удаляются.
3. Таблица соответствия обновляется непрерывно по мере появления новых максимумов.

## Конфигурация

### `config.yml`

```yaml
path: /data
train: images/train
val: images/train
names:
  0: бортпроводник(женский пол)
colors:
  0: [255, 0, 255]
model_names:
  - rivc-cnn-standart-0.3
model_files:
  - yolov8s90_1600_130623.pt
uniform:
  general_summer_outside_steward_woman:
    - бортпроводник(женский пол)
    - пилотка
uniform_consist:
  - бортпроводник(женский пол)
  - жакет
```

### `uniformmatch.csv`

Сопоставление обнаруженных классов и компонентов униформы.

- **Разделитель:** `;`
- **Кодировка:** `utf-8-sig`
- **Строки:** названия обнаруженных классов (отдельные предметы или комбинации) плюс строки `min` и `max`.
- **Столбцы:** отдельные компоненты униформы.
- **Значения:**
  - `1` — компонент присутствует в комбинации / допустим,
  - `2` — компонент является нарушением при обнаружении,
  - `0` / пусто — не относится.

Строки `min` и `max` задают допустимые количества по каждому компоненту. Логика классификации суммирует вклады всех обнаруженных классов в каждый компонент и сравнивает итог с `min`/`max`.

## Логика классификации

1. Фильтрация детекций по порогу уверенности.
2. Удаление дубликатов: перекрывающиеся рамки одного класса (IoU выше 50 % от площади меньшей рамки) отбрасываются.
3. Для каждого обнаруженного класса находится строка в `uniformmatch.csv`; счётчик добавляется ко всем компонентам, где значение ячейки `> 0`.
4. Суммирование вкладов по компонентам и сравнение с `min`/`max`:
   - `min <= count <= max` → компонент присутствует, нарушения нет;
   - иначе → `несоответствие количества` или `отсутствует`.
5. Классы-нарушения и неожиданные предметы (не сопоставленные ни с одним компонентом текущего комплекта) выводятся отдельными строками `нарушение_N`.

## Модель

Используется Ultralytics YOLOv8:

- По умолчанию: `yolov8n.pt` (скачивается автоматически).
- Пользовательские: поместите `.pt` в `models/` и укажите в `model_names` / `model_files` в `config.yml`.

Модель ожидает RGB на входе; приложение конвертирует BGR-кадры в RGB перед инференсом.

## Зависимости

- `ultralytics` — модели YOLO
- `streamlit`, `streamlit-webrtc` — интерфейс и WebRTC-стриминг
- `opencv-python` — ввод/вывод изображений и видео

Версии указаны в `requirements.txt`.

## Замечания и ограничения

- Логика классификации табличная; чтобы добавить новый тип нарушения, нужна новая строка в `uniformmatch.csv` со значением `2` в нужном столбце, либо отдельный класс с `(нарушение)` в имени.
- Подавление дубликатов работает по IoU на меньшей рамке. Для сильно перекрывающихся разных классов подавление не применяется.
- В режиме камеры максимумы сохраняются в течение всей сессии; для сброса перезагрузите страницу.
- Для видео используется кодек `avc1` с откатом на `mp4v`. Если ни один не доступен, включите шаг конвертации через `ffmpeg` в `main.py`.
